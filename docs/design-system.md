# AI DevOps Open Suite 界面设计系统

本规范是 DevCycle、InfraScout、FleetScope 和 ReleaseGuard 的共同发布基线。产品可以采用适合领域的信息架构，但不得重新定义同名语义、交互反馈或基础视觉令牌。

C2 按用户提供的新版视觉参考更新。实现的唯一来源是[共享界面规范](unified-ui.md)及其中的 CSS / JavaScript；所有现有和新增页面都必须使用同一套浅色、深色、随系统主题与响应式组件。

## 设计目标

- 面向需要反复扫描、比较和执行操作的研发运维用户，优先信息密度、确定性和可追溯性。
- 第一屏提供清晰的工作入口；欢迎区只展示真实状态、简明引导和可执行操作。
- 图标承担识别，文字承担确定含义；不可只靠颜色、形状或悬停传达状态。
- 默认本机运行、最小权限和证据边界要在相关操作附近可见，但不反复打断工作流。

## 共同令牌

四个产品的 `:root` 必须提供以下 `--suite-*` 令牌；产品令牌只能引用或扩展它们。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--suite-bg` | `#f7f9fd` | 浅色页面背景 |
| `--suite-surface` | `#ffffff` | 工具、表格和重复项目表面 |
| `--suite-surface-soft` | `#f0f4fc` | 次级表面与悬停 |
| `--suite-ink` | `#141b2b` | 主文字 |
| `--suite-muted` | `#5d6b82` | 次要文字 |
| `--suite-line` | `#e0e7f2` | 普通分隔线 |
| `--suite-line-strong` | `#bdcbe0` | 控件边界 |
| `--suite-accent` | `#4f46e5` | 主操作与当前状态 |
| `--suite-accent-strong` | `#4338ca` | 悬停与焦点表面 |
| `--suite-accent-soft` | `#eeecff` | 选中背景 |
| `--suite-success` | `#15803d` | 成功 |
| `--suite-warning` | `#975407` | 警告 |
| `--suite-danger` | `#be263c` | 失败与危险操作 |
| `--suite-info` | `#2563eb` | 信息 |
| `--suite-brand` | `#4f46e5` | 套件品牌识别 |
| `--suite-focus` | `#2563eb` | 键盘焦点 |
| `--suite-radius` | `14px` | 卡片与单项容器圆角 |

以上为浅色值；深色值由共享文件的主题令牌统一提供，不用图片反色或灰度滤镜。字体栈沿用系统字体与中文后备字体；正文使用 14px，紧凑元数据使用 11-12px，欢迎区标题按视口收敛。图表保留多个有意义的彩色序列。

## 共同组件

### 顶栏与模块切换器

- 顶栏第一视觉信号必须包含产品名和 `AI DEVOPS OPEN SUITE`。
- 模块切换器顺序固定为 DevCycle、InfraScout、FleetScope、ReleaseGuard。
- 每项使用 Lucide 图标、产品名和统一描述：研发交付、基础设施发现、原生监控、发布门禁。
- 当前产品同时使用 `aria-current="page"`、强调色背景和品牌色左边框。
- 点击外部或按 `Escape` 关闭；键盘关闭后焦点返回触发按钮。

### 控件与反馈

- 桌面控件最小高度 38px，移动端主要触控目标最小高度 40px。
- 图标按钮必须有 `aria-label` 和可发现的 `title`；清晰命令使用图标加文字。
- 焦点统一为 `3px solid var(--suite-focus)`、`outline-offset: 3px`，覆盖链接、按钮、输入、选择、摘要和可聚焦自定义控件。
- toast 默认中性；成功、错误和信息必须使用显式变体。字段错误优先在字段附近持久显示，toast 只作补充。
- 危险操作必须说明影响范围并要求明确确认，规则不因屏幕宽度改变。

### 数据状态

- 加载、空数据、部分陈旧、失败、无权限均要有独立状态和下一步操作。
- 状态始终使用文字；图表和拓扑还必须提供线型、编号、形状或表格明细等非颜色编码。
- 后台轮询不得销毁用户焦点、输入、选择或展开状态；用户正在操作时暂停自动重绘。
- 时间戳不放入持续播报区域。读屏只播报状态转变、失败恢复和有意义的样本变化。

### 对话框

- 使用原生 `<dialog>`，每个对话框通过 `aria-labelledby` 绑定可见标题。
- 打开后焦点进入首个安全操作；关闭后返回触发控件；`Escape` 可退出非强制流程。
- 破坏性流程默认焦点不能落在确认按钮，错误信息使用 `role="alert"`。

## 响应式基线

- `1100px`：宽工作区收敛多列布局。
- `760px`：主导航切换为可通过按钮及键盘操作的移动侧栏。
- 手机布局中主内容占满可用宽度；表格可在自身容器内滚动，不允许整页横向溢出。
- 产品可增加局部断点，但不能隐藏唯一功能入口、安全状态或控件可访问名称。
- 固定格式区域必须声明稳定的网格、最小宽度或 `aspect-ratio`，动态内容不得推动工具栏或控制区跳动。

## 领域差异

- DevCycle 保留需求主从布局、五阶段交付导航和 AI 紫色辅助语义。
- InfraScout 保留资产浏览、漂移审核、数据库视图和右侧资产抽屉。
- FleetScope 保留密集侧栏、时序图、拓扑、告警和数据接入视图；图表色板属于领域扩展。
- ReleaseGuard 保留发布阶段条、打印报告、观察窗口和不可变批准界面。

这些差异不得覆盖共同令牌、套件切换器、焦点、状态反馈和响应式安全规则。

## 发布验收

每次候选发布至少完成以下检查：

1. 在 1440px、834px、390px 三档真实浏览器视口检查四个产品及统一入口，分别检查浅色和深色，无整页横向溢出、遮挡或不可读控件。
2. 仅用键盘完成主导航、模块切换、筛选、对话框打开与关闭、核心提交操作。
3. 页面有可跳到主要内容的链接；每个活动视图有一级标题；动态错误、决策和长期任务状态有正确的 live region。
4. 所有可见表单控件有可访问名称，所有对话框有标题绑定，所有图标按钮有名称。
5. 自动轮询期间，输入框、表格行和操作控件焦点不丢失，展开与选择状态不被覆盖。
6. 运行模块测试、静态检查、竞态检查和跨平台构建；截图更新后核对其确实来自当前候选版本。

任一核心流程不可用、唯一入口在目标视口消失、发布决策无法被读屏感知或页面发生整页横向溢出，均视为发布阻断。
