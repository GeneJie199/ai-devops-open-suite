# 原生可观测架构决策

状态：Accepted
日期：2026-08-12

## 决策

FleetScope 自己实现并拥有默认的数据平面：Agent 采集、节点身份、可靠队列、批次去重、时序与事件存储、查询、规则、告警、变化处置和 Web 界面。套件的完整运行链路不得要求用户另行部署 Prometheus、OpenTelemetry Collector、InfluxDB、VictoriaMetrics 或其他采集与存储服务。

Prometheus 文本、Influx Line Protocol 和 OTLP/HTTP JSON 保留为兼容入口。它们只把外部数据转换为 FleetScope 的版本化批次协议，不成为内部主模型，也不改变原生 Agent 是默认数据来源这一事实。

## 原因

- 小团队需要可下载即运行的完整产品，而不是多个外部组件的安装说明。
- 节点身份、采集新鲜度、变化证据和发布观察必须落在同一套可审计语义中。
- 兼容生态协议有利于迁移和混合环境，但不应反向决定产品架构。
- 有界内置存储能满足当前 30 天保留和小中型节点集；容量边界必须显式暴露，超限必须报错，不静默丢弃无关活跃数据。

## 当前数据链路

1. Agent 直接读取 Linux procfs/syscalls，并直连 Nginx、Redis、PostgreSQL、MySQL、Docker Engine、HTTP/TCP/TLS 与文件日志目标。
2. 各采集器使用可独立配置的周期、确定性错峰、并发上限和超时；指标与事件进入不同的持久化 spool。
3. 队列满时 Agent 会先排空已确认的历史批次再重试当前批次；中心恢复后不会因满队列永久停滞。
4. Center 以节点凭据鉴权，以 `node_id + source + sequence` 去重，写入按日分段的 NDJSON 存储；启动时可从数据段重建去重序号和内存索引。
5. Catalog、查询、资源组、规则、告警、事件和 ReleaseGuard 指标回归都直接读取该存储。
6. 生命周期 Schema 固定 `telemetry.batch/v1`、`event.batch/v1` 和 Fleet 节点报告边界。

## 明确边界

- 当前不是无限保留、无限基数的云级 TSDB；默认 30 天保留，并分别限制序列基数、保留样本总数、批次大小、事件数量，以及每节点报告历史的条数和字节数。超限显式拒绝或原子压缩，不静默丢弃无关活跃数据。
- 当前主要采集目标是 Linux 服务器；其他平台保证 Center/CLI 可构建，但不会伪装成拥有同等系统采集覆盖。
- 兼容入口不宣称完整实现相应生态的全部远程写入、查询语言或控制面协议。
- 企业级多租户 IAM、跨区域复制和高可用集群不在本次开源发布范围内。
